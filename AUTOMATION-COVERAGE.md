## Scope and evidence

Source union, not preprocessed per game/build. No runtime availability or semantic parity claim.

Inventory includes every declared click/execute, double-click, keyboard, drag/drop, new-text, checked, change, mouse-down and header-click/drop bindings in xEdit DFM files and dynamic main-form bindings, every explicit automation registration, every runtime-policy ledger entry, and literal AddFunction/AddGet/AddSet registrations in xEdit/JvI. Child dialogs are inventoried separately. Rendering/lifecycle callbacks, inherited external-component behavior, RTL adapter registrations, constants/classes, and computed registration names are not exhaustively parsed. Do not interpret this as proof that every conceivable UI gesture is covered.

All routes below are source-reviewed and **runtime-not-verified** in this checkout. Policy admission proves only permission for that symbol/action; it does not prove a recipe compiles or reproduces GUI behavior. Unsupported game/record/target combinations must fail before mutation.

## Prerequisites and persistence

Use a loaded daemon session and probe system.capabilities for current support and consent state. Structured mutation requires -IKnowWhatImDoing, edit mode and an editable non-protected target. Game, signature, parent and schema predicates remain native; a source-union row is not an all-games promise. Use elements.edit_capabilities/assign_templates before structural edits. Jobs require jobs.start, then jobs.get; each poll advances one registered target unit, with cancellation between units. Native work within a unit blocks that poll. Script routes require Agent/ storage, policy admission and budgets, and do not inherit every structured-command guard.

Plugin changes stay in memory until session.save. Check both dirty and pendingShutdownCount; session.flush is terminal and refuses unsaved changes unless force:true accepts loss. Confirm durable output by loading it in a fresh process. scripts.write/delete change script files immediately. Generated external files need separate output-path and durability contracts.

## Agent workflow recipes

These recipes are source-derived and require game-backed verification. Substitute real loaded identities; inspect every response and stop on errors.

1. **Inspect and edit a field:** `records.find_by_form_id` or `records.find_by_editor_id` -> `records.get` -> paged `elements.children` -> `elements.edit_capabilities` -> `elements.set_value`/`elements.set_native_value` -> `elements.get`. Do not feed truncated preview text back into writes. Full read: elements.get_value; previewMetadata marks trimmed/truncated summaries. Inline string writes preserve detected UTF-8 and reject lossy encoding; runtime acceptance for #2/#3 is pending.
2. **Create an override patch:** `files.create` -> `records.copy_into` with `mode:"override"`, `addRequiredMasters:true`, explicit source/target -> inspect returned locator -> field edits. Deep-copy and overwrite flags are explicit; wrapper/spawn-rate modes are missing. Copy errors may leave masters added (#4).
3. **Validate/clean:** `jobs.start` with a validation kind and `target:{files:[...]}` -> `jobs.get` -> paged `jobs.findings`. For cleaning use `dryRun:true`, review findings, then a separate start with `dryRun:false`. Do not apply ITM cleaning until #1 is fixed and verified.
4. **Persist:** `session.get_dirty_state` -> `session.save` with explicit files or `all:true` -> inspect dirty/pending state -> `session.flush` -> wait for exit -> restart and independently reread the plugin. Do not default to `force:true`.
5. **Primitive script candidates:** write an Agent/ script with `scripts.write`, then `scripts.run` with explicit targets. An example Process body is `SetIsPersistent(e, True);` followed by `Result := 0;`. Equivalent VWD primitive is `SetIsVisibleWhenDistant(e, True);`, and explicit-master primitive is `AddMasterIfMissing(GetFile(e), 'Dependency.esm');`. These are admitted symbols, not verified complete workflows; native child-group relocation, dependency rules and script-target policy must be tested. Full Initialize/Process/Finalize lifecycle, budgets, failure details and no implicit save still apply.
